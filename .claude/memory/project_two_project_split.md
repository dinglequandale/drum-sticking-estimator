- **`ergonomic_sticking_estimator/` — ACTIVE.** New, more tractable goal: given drum **audio only** (mp3 uploads, no video), output the **most economical / ergonomic / idiomatic** sticking a competent **right-handed** player would choose, with calibrated uncertainty. NOT recovering the drummer's actual choice.

**Why the reframe matters (the key insight):** the old problem's bottleneck was acquiring sticking-labeled data for the grammar. The new objective's backbone is **parametric biomechanics** (reach, speed floor, rebound, accent) which needs **no labeled corpus**. Confidence changes meaning: P(economical/idiomatic choice), not P(actual hand). The flag becomes **low margin between top candidate stickings** — which is also a **don't-care** (if sound+physics don't separate `RLRR|LRLL` from flat `RLRL`, either is fine). Data need collapses from thousands of labeled phrases to ~10 clips for **inter-drummer-agreement calibration** eval.

**The active design — segmental (grouping-based) Stage 5** (`ergonomic_sticking_estimator/DESIGN_STAGE5_SEGMENTAL.md`, the build contract): cover the hand-strike stream with metric **cells**, dress each in a sticking **template** (hand tokens + accent pattern), minimize total cost = `C_accent + C_feasible + C_reach + C_idiom` per cell + `C_seam` between cells, decode with **semi-Markov Viterbi** over metric-boundary breakpoints, confidence = template margin. Mandatory **generic fallback template** (physics-only, no idiom discount) so the vocab grants discounts never exclusivity (guards the spec's ban on a hard pattern bank). v1 fixes right-handed/crossed (`lead=R` = free phase anchor); feet are decoder anchors, not template slots; templates are surface-agnostic so tom-count is additive.

**Progress (2026-07-01):** built + unit-verified `src/templates.py` (10 canonical rudiment cells + mirrors + fallback), `src/scoring.py` (`score_accent`, `pair_feasibility` — the single per-adjacency feasibility term, run-length aware), and `src/decoder.py` (semi-Markov decoder, step 3 DONE). Key design lessons baked in: (1) feasibility must be **segmentation-invariant** — charge one shared `pair_feasibility` at every adjacency and thread same-hand run-length through the DP state `(exit_hand, exit_run)`, else the decoder farms a seam-alternation reward by making every note a length-1 cell; (2) the metric anchor must pin ONLY the downbeat phase (lead=R on the integer beat), NOT map every 16th to alternating R/L — an 'e/a→off-hand' rule hardcodes RLRL and fights doubles-at-speed; (3) global L↔R symmetry means without the metric anchor every hit is honestly 0.5 (relative pattern determined, absolute labels a coin flip). Verified on synthetic streams: fast even roll→RRLL doubles, slow→alternation, ambiguous→flagged. NOT yet run on real ADTOF audio (needs pipeline wiring). Next options: step 4 (`C_reach` + surface-aware continuity — fixes moderate-tempo phase & cross-surface fills), OR wire `pipeline.py` to run end-to-end on `../samples/`, OR the tom module.

**Tom sub-classification — BUILT + validated (2026-07-01), `src/stage1p5_toms.py`.** ADTOF's `adtofAll` merges all toms into one class. Fix: per-clip unsupervised clustering — estimate each tom hit's pitch (spectral peak in a physical search band, NOT a fixed cutoff), cluster in log-Hz via KMeans with a **dimensionless silhouette floor** (Konrad's directive: no fixed pitch thresholds, adapt to each kit's tuning), rank clusters high→low pitch, relabel surfaces `tom0`(rack)..`tomN`(floor). Wired into `pipeline.py` between Stage 1 and 2 (`config.subclassify_toms`). **Robustness win:** found the SAME 3 toms at the SAME pitches (~157/117/75 Hz) in both sample_2 and sample_3 (same kit, different clips), and correctly left sample_1's 6 pseudo-tom hits UNsplit. Step 4 `C_reach` will map tom0/1/2 → left→right X to finally use this (recovers the tom-sweep signal behind "three-across → RLL").

**Step 4 (`C_reach` + nearest-hand) — BUILT (2026-07-01), `src/decoder.py` + `KIT_GEOMETRY` sub-toms.** Two terms: (1) **reach-travel** — a same-hand adjacency on the SAME surface is a rebound double (double logic), on a DIFFERENT surface is a hand *traveling* (`_reach_travel` = w_reach·dist·(0.25+0.75·speed_frac), run-length resets). This was the key correctness fix — before, the `LL`-across-two-toms in RLL/LRR was mis-penalized as a gratuitous slow double, killing around-the-kit stickings. (2) **side-affinity** (`_side_affinity`, nearest-hand: R favors kit-right, L kit-left; per-hit absolute, `w_side=0.3`). Geometry keyed on `KIT_GEOMETRY[handedness_style]`, tom0..tom3 placed left→right by pitch rank. **Result on the sample_2/ batch:** structural sticking clearly improved (RLL emerges in rll_lrr, RKLK clean in rk_lk_rklk, no false doubles/runs) BUT confidence stayed low (~0.52-0.57, mostly flagged). Lessons: reach-travel needs a speed-INDEPENDENT base cost or slow same-hand cross-tom moves are ~free and side-affinity farms one-hand runs (RRRR); w_side=0.6 over-pulled and hurt rk_lk confidence → dialed to 0.3.

**KEY OPEN INSIGHT — relative vs absolute confidence (2026-07-01).** The pervasive flagging is largely HONEST: the model is confident about the *relative* pattern (it finds RLL) but genuinely uncertain about *absolute* L/R labeling, and `confidence=max(P(R),P(L))` measures the absolute question. On symmetric material (rll_lrr literally contains both RLL and LRR) flagging absolute lead is correct; cranking confidence would fabricate it. The real lever is **separating relative-pattern confidence from absolute-hand confidence** in the output ("confidently an RLL grouping, lead hand uncertain") — NOT more weight-tuning. This likely matters more than any remaining Step-4/5 term. Validate confidence via the inter-drummer eval, not the 6 rough-GT clips.
